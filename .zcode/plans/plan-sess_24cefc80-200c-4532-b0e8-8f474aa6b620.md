# super-silly — Autonomous SillyTavern + Ollama + Telegram (revised)

Same architecture as approved draft — single Docker image (SillyTavern + Ollama + Autolife plugin/UI), with these revisions from your feedback:

## Changes from your feedback

1. **Models (HuggingFace GGUFs via Ollama's `hf.co` namespace — no Modelfile needed):**
   - Default `OLLAMA_MODEL=hf.co/ReadyArt/Dark-Scarlett-27B-v2.0-GGUF:Q4_K_M` (~16–17 GB → fits Tesla P40 24 GB with context headroom; deployment target).
   - Fallback `OLLAMA_FALLBACK_MODEL=hf.co/ReadyArt/Dark-Desires-12B-v1.0-GGUF:Q4_K_M` (~7 GB → fits RTX 5060 16 GB; recommended for dev on this machine).
   - Entrypoint: pull primary; on failure (network/disk/timeout) pull fallback. Dev compose override sets the 12B as primary.
   - Model is a **runtime setting, not baked in**: engine's `ensureModel()` calls Ollama `/api/pull` on demand when a selected model isn't local yet.
2. **Model switching from both surfaces (v1 scope):**
   - ST UI: Autolife panel gets a model picker — lists local Ollama models (via plugin proxy of `/api/tags`) plus a free-text field for any `hf.co/...:tag`; sets global or per-character model.
   - Telegram: `/model` (current), `/model list` (local + the two configured presets), `/model use <name>`, `/model pull <name>` (streams pull progress into chat).
3. **Telegram command suite (v1 core, built on an extensible command registry so adding commands later is one file edit):**
   - `/start /help` — bind chat, show commands; `/status` — character's live life-state (activity, availability, pending queue); `/pause /resume`
   - `/chars` — list Autolife-enabled characters; `/switch <name>` — rebind this Telegram chat to another character/chat
   - `/model ...` — as above
   - `/upload` — send a `.png` or `.json` card as a document → plugin validates (valid `chara_card_v3` + Autolife block), imports it into SillyTavern's characters dir, optionally binds; errors reported back in-chat
   - Future commands (registry stubs with "not yet implemented" replies): `/schedule` (view/edit), `/journal`, `/newchat`, `/persona`
4. **GPU notes baked into README/compose:** image works on both dev (RTX 5060, Blackwell — needs recent Ollama builds, which we use) and deploy (Tesla P40, Pascal CC 6.1 — officially supported by Ollama, requires driver ≥550; on TrueNAS SCALE pin the NVIDIA driver since 550 is the last Pascal-supporting branch). Compose ships with GPU reservation + `OLLAMA_MODEL`/fallback envs; includes a `dev` override file for the 5060 (12B primary).

## Unchanged core of the plan (from the draft you approved)

- **Autolife spec v1.0** (`spec/autolife-spec-v1.md`): extension on Character Card V3 at `data.extensions.autolife` — `timezone`, weekly `schedule[]` blocks (days/start/end/activity/availability/mood), `behavior` (quick_reply_chance, delay_minutes_min/max, busy_delay_multiplier, ignore_chance, catch_up, avg_message_length), `initiative` (enabled, min_gap_minutes, max_per_day, followup_on_unread_hours), `relationship.initial`, `journal.enabled`. Runtime state (pending jobs, cooldowns, affinity, journal, bindings) lives engine-side in `data/<user>/autolife/`, never written into the card.
- **Server plugin `plugins/autolife`** (zero npm deps, Node ≥20 built-ins): `index.js` (init(router), scheduler start) + `src/` modules — `card-io.js` (PNG tEXt chunk read/write, prefer `ccv3`, preserve other chunks), `schedule.js` (pure `evaluate(card, date)`, delay sampling, injectable RNG), `llm.js` (Ollama `/api/chat` client + prompt builder: card fields + texting-style directive + life context + chat tail + `ensureModel`), `chat-store.js` (appends ST-format JSONL: header + `{name,is_user,is_system,mes,send_date,extra,swipes}`; creates chats with greeting), `engine.js` (30s tick: respond-now/delay(t)/ignore decisions × availability, due delayed replies, initiative rolls, catch-ups), `telegram.js` (Bot API long-poll, allowlist, bindings, typing indicator, rate-limited outbound), `commands.js` (the command registry above), `routes.js` (`/api/plugins/autolife/{status,sessions,characters,card,bindings,settings,trigger,model}` + `GET /events` SSE).
- **UI extension `autolife-ui`** (`data/default-user/extensions/autolife-ui`): Extensions-drawer panel — per-character enable, 7-day schedule grid, behavior/initiative sliders, model picker; Life Monitor window (live activity, pending queue, force-initiate, Telegram token/binding form stored server-side, SSE updates, reload-chat on engine writes).
- **Card tools + examples**: `tools/card-tools.mjs` (dependency-free `validate / inspect / create --template / embed`), `cards/examples/` (2–3 characters as JSON + embedded PNG, CLI-validated).
- **Docker** (`docker/`): multi-stage Dockerfile — Ubuntu 24.04 final stage (glibc for Ollama), Ollama binary + runners copied from `ollama/ollama:latest`, Node 22 binary copied from `node:22-bookworm-slim`, SillyTavern cloned from `release` branch + `npm ci` + webpack in build stage, plugin + seeded config (`listen: true`, `enableServerPlugins: true`, `whitelistMode: false`, browser launch off) and seeded data (UI extension, best-effort preselected Ollama connection) baked in. `entrypoint.sh`: seed `/config`+`/data` volumes if empty → `ollama serve` in background → wait for `:11434` → background model pull with fallback → `exec node server.js --listen`. Volumes `/config`, `/data`, `/ollama`; port 8000. `docker-compose.yml` (+ `compose.dev.yml` override) with GPU reservation and env pass-through (`OLLAMA_MODEL`, `OLLAMA_FALLBACK_MODEL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_CHAT_IDS`).
- **Repo layout**: `README.md`, `spec/`, `plugin/`, `ui/`, `tools/`, `cards/examples/`, `docker/`, `tests/`.
- **Build order & verification**: spec → plugin core + unit tests (frozen clock, mocked Ollama, `node --test` on host) → telegram transport + commands → UI extension → CLI + example cards → Docker build + smoke test on this machine (5060, 12B) — ST reachable on :8000, `/api/plugins/autolife/status` 200, Ollama answers a test generation, bot verified against a mocked Bot API when no token is set → README (quickstart, BotFather setup, TrueNAS/P40 deployment section, security notes).

Phase 2+ (unchanged): burst multi-messages, typing-speed simulation, deep relationship progression, journal-driven life events, group chats, media messages, Discord transport, charx asset polish.
